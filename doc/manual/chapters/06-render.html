繪製：攝影機、燈光、網格

RenderPlugin 把有 Camera、Light、MeshRenderer 元件的實體同步成 three.js 物件並畫出來。遊戲邏輯只碰元件，不需要直接操作 three.js 的場景。

RenderPlugin 設定

WebGPU

引擎用 WebGPU 繪製（three.js 的 WebGPURenderer）；瀏覽器不支援 WebGPU 時，它會自動改用 WebGL2 畫，遊戲不用另外處理，所有功能（後製特效、自訂著色器、節點圖、粒子、介面）兩種情況都能用。

  • render.gpuApi 是實際用的圖形介面：'webgpu'，或 'webgl2'（不支援 WebGPU 時的備援）。
  • WebGPU 要先非同步初始化（取得 GPU），完成前不繪製；要等它的話寫 await render.ready。
  • 材質是 three.js 的節點材質：一般的材質（MeshStandardMaterial…）會自動轉換；自訂著色器用 TSL（three.js 的著色器節點語言，用 JavaScript 函式組出著色器，見更多功能的自訂著色器）。自己寫 GLSL 的 three.js 材質（ShaderMaterial、onBeforeCompile）與 EffectComposer 不能用。
  • 遊戲裡 import … from 'three' 拿到的是 three/webgpu（打包設定已經對應好），WebGL 的繪製器不會被打包進來。

元件

元件常用欄位
Camerakind（perspective／orthographic）、fov、near、far、size（正交的可視半高）、priority（多台攝影機時最高的負責繪製）
Lightkind（ambient／hemisphere／directional／point／spot）、color、intensity、castShadow、distance、angle
MeshRenderergeometry、material、castShadow、receiveShadow、visible
SceneObjectobject：直接放任何 three.js 物件（例如載入的模型、自己組的群組）

攝影機、平行光、聚光燈朝向自己的 -Z 方向。建立時用 spawn.camera／spawn.light 的 target 指定看向哪裡；之後要改朝向時用 math.lookAt(transform, 目標)。

簡潔的寫法：小工具與描述

常用的攝影機、燈光、網格有小工具，放在 spawn 底下，一行完成「建立實體＋位置＋朝向」；位置可以寫 [x, y, z]。每個都回傳建立的實體，用 const 接住，之後可以再加元件或移動它。網格的幾何與材質可以寫描述，不用 import three.js：

寫法說明
spawn.camera(world, { position, target, fov })攝影機（預設在 [0, 2, 6] 看向原點）
spawn.defaultLights(world, { intensity, shadows })半球光＋從斜上方照下的平行光；回傳 { ambient, sun }
spawn.light(world, { kind, position, target, … })任一種燈光
spawn.mesh(world, { geometry, material, position, rotation, scale })網格
spawn.grid(world, { size, divisions, color })地面格線

幾何描述：{ box: 1 }、{ box: [寬, 高, 深] }、{ sphere: 半徑 }、{ plane: [寬, 高, 橫向分段, 縱向分段] }、{ circle: 半徑 }、{ cylinder: [半徑, 高] }、{ cone: [半徑, 高] }、{ capsule: [半徑, 長] }、{ torus: [半徑, 管徑] }、{ torusKnot: [半徑, 管徑] }、{ dodecahedron: 半徑 }（還有 icosahedron、octahedron、tetrahedron）。都可以加 rotation: [x, y, z]（先把幾何轉好，例如立起來的硬幣）和 offset: [x, y, z]（移動幾何，例如以底部為中心縮放的方塊 { box: 1, offset: [0, 0.5, 0] }）。

材質描述：'#ffb347'（顏色簡寫，等於 standard）、{ standard: { color, roughness, metalness, emissive… } }、{ physical: {…} }、{ basic: {…} }（不受光照）、{ lambert: {…} }、{ phong: {…} }；參數和 three.js 材質一樣，另外：

  • side：'front'、'back'、'double'；blending：'normal'、'additive'（發光特效）、'subtractive'、'multiply'。
  • 貼圖直接寫網址，自動載入：{ standard: { map: 'textures/wood.png', repeat: 4 } }（repeat 重複幾次，wrap 可以是 'repeat'、'clamp'、'mirror'）。normalMap、roughnessMap 等也一樣；同樣的網址與設定共用同一張貼圖。
  • 要在執行中修改材質（例如點擊後換顏色、依狀態改發光）時，用 create.material(描述) 建立自己的一份（不會和其他物件共用），回傳的就是對應的 three.js 材質（{ standard } → MeshStandardMaterial）。

常用的型別名稱（MeshStandardMaterial、Material、Texture、Object3D…）可以從 @engine/render 引用；向量、四元數、顏色從 @engine/math 引用（就是 three.js 的類別）。一般的遊戲程式不需要 import three。

描述建立後不要直接改裡面的值（例如 desc.standard.color = …）；要換外觀時指定一個新的描述：world.require(e, hero.MeshRenderer).material = '#ff0000'。需要實際的 three.js 物件時用 render.getObject(實體)。自訂著色器、載入的模型、貼圖等，照樣直接給 three.js 物件。

攝影機繞轉控制

在攝影機上加 OrbitControl，就能用滑鼠或手指繞著目標點轉動、縮放、平移（像模型檢視器）：

操作滑鼠觸控
轉動左鍵拖曳單指拖曳
縮放滾輪雙指捏合
平移右鍵拖曳，或 Shift + 左鍵拖曳雙指一起移動

點到 2D 介面（按鈕、滑桿…）的操作不會轉動攝影機。放開後有一點慣性（damping，0 為沒有）。這本手冊的所有範例都預設開啟（範例的執行環境設定了 RenderPlugin.defaults.orbitControls），試著拖曳下面的畫面：

其他設定：rotate、zoom、pan（關掉某個操作）、rotateSpeed／zoomSpeed／panSpeed、minPolarAngle、enabled。正交攝影機縮放時改變它的 zoom。

不想自己加元件時，new RenderPlugin({ orbitControls: true }) 會自動控制目前的攝影機：使用者第一次操作前不會動攝影機，遊戲自己的攝影機動畫照常運作；沒有操作時，遊戲移動攝影機後，下次會從新的位置接著轉。

攝影機要是最上層的實體（沒有父節點）。手冊範例不想要這個功能時，寫 new RenderPlugin({ orbitControls: false })。嵌在網頁裡時可以設 wheelNeedsFocus: true：先點一下畫面，滾輪才會縮放，捲動頁面時不會誤觸。

攝影機跟隨與晃動

攝影機加上 CameraFollow：平滑地跟著目標、一直看著它，可以限制攝影機的範圍。shakeCamera(world, 攝影機, 0~1) 讓畫面晃一下（受傷、爆炸、落地），可以疊加，會自己慢慢停下來。下面的球自己亂走，攝影機跟著它；每 2 秒晃一下：

CameraFollow 欄位說明
target跟隨的實體（null 或被銷毀時攝影機不動）
offset攝影機相對目標的位置（預設後上方 (0, 3, 6)）
offsetSpace'world'：固定方向（俯視、橫向捲軸）；'target'：跟著目標的左右轉向，一直待在它背後（第三人稱）
smoothTime位置的平滑時間（秒）；0 立刻跟上（預設 0.25）
lookAt、lookOffset、rotationSmoothTime一直看著目標的哪裡（例如頭部 (0, 1.5, 0)），轉向的平滑時間
bounds{ min, max }：攝影機不會超出這個範圍（不要拍到地圖外面）
enabled暫停跟隨
  • 第一幀直接就位（不會從原點飛過去）；傳送或換場景之後要直接跳過去，呼叫 render.snapCamera(攝影機)。
  • 晃動只加在繪製用的攝影機上，不會改到攝影機的 Transform：不會越晃越偏，也不會和自己寫的攝影機程式或 OrbitControl 互相干擾。設定：shakeCamera(world, cam, 0.5, { maxOffset, maxAngle, decay, frequency })（位移公尺、旋轉度數、每秒衰減、快慢）。
  • 跟隨和滑鼠繞轉（OrbitControl）不要放在同一台攝影機上；有 CameraFollow 的攝影機，orbitControls: true 也不會自動加上繞轉控制。
  • 範例專案 official-demo-000-start：按 C 在「自動環繞」和「跟隨方塊」之間切換；爆炸、用力撞擊時畫面會晃。

繪製圖層與子畫面

圖層決定哪台攝影機畫哪些物件：物件加上 RenderLayer 指定它在哪些圖層，攝影機加上 CameraLayers 指定它畫哪些圖層。CameraViewport 把另一台攝影機畫在畫面的一塊範圍裡（小地圖、後照鏡、子母畫面）。下面右上角是俯視的小地圖：黃色的大記號只在 minimap 圖層，主畫面看不到它。

  • 沒有 RenderLayer 的物件在 'default' 圖層；沒有 CameraLayers 的攝影機只畫 'default'。圖層名稱第一次用到時自動配編號（最多 32 個）。
  • RenderLayer 套用到物件與它的子物件（例如模型裡的每個零件）；移除後恢復成 'default'。
  • 燈光預設照亮所有圖層；給燈光 RenderLayer 時只照亮那些圖層。
  • render.pick 只會選到主畫面攝影機看得到的圖層。
  • CameraViewport 的 x、y、width、height 是畫面的比例（0~1，從左上角算起）；background: null 時是透明的，直接疊在主畫面上。有 CameraViewport 的攝影機不會被選為主畫面，在主畫面（含後製）之後、2D 介面之前繪製，不套用後製。
  • 三個元件都能存進場景檔（圖層寫成 layers="default minimap"），3D 場景編輯器的屬性面板可以直接編輯。
